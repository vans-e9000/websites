## Scroll & Reveal Motion

The page reveals content as it scrolls. Measured over a full end-to-end scroll pass:

- **fade in** - 38 elements (64% of 59 reveals)
- **slide up** - 11 elements (19% of 59 reveals)

**Stagger:** siblings do not fire together - each one starts 25ms after the last. Reproduce it with an index-based delay, not one shared animation.

### Paste-ready reveal CSS

```css
.reveal {
  opacity: 0;
}
.reveal.is-visible {
  animation: opacity 500ms cubic-bezier(0.4, 0, 0.2, 1) both;
}
/* stagger: set --i on each sibling (0, 1, 2 …) */
.reveal.is-visible { animation-delay: calc(var(--i, 0) * 25ms); }

@media (prefers-reduced-motion: reduce) {
  .reveal, .reveal.is-visible { animation: none; opacity: 1; }
}
```

### How to wire it

- Observe with a single `IntersectionObserver` at `threshold: 0.15` and `rootMargin: "0px 0px -10% 0px"`, add `is-visible`, then `unobserve` - every measured reveal fired once on entry, none replayed on scroll-back.
- Stagger by writing `--i` on each child (index order) so the delay is `25ms �- index` - the measured step.
- The page already declares `prefers-reduced-motion` overrides - ship the guard above; without it the rebuild is less accessible than the original.
- A smooth-scroll library is present (Lenis) - scroll position is virtualised, so native `IntersectionObserver` roots may need the library's container.
- 1 in-page anchor link navigate between bands, so scroll-margin on section targets matters.

### Mobile adaptation

- **Navigation:** is swapped by width rather than by a menu button - `'.header-break\:flex' shown ≥1000…`, `'.header-break\:grid' shown ≥1000…`.
- **Visibility:** 7 selectors hidden and 2 revealed by width (other, nav).

### Modern CSS in play

- **Container queries** are in use - components size to their container, not the viewport. Port the `@container` rules or the layout will not match at intermediate widths.
- **`aspect-ratio`** holds media boxes instead of padding hacks.
- **Intrinsic grids** - `auto-fit` / `minmax()` do the column maths instead of breakpoints.
- **`prefers-reduced-motion`** is honoured by the page itself - replicate the override, do not drop it.
- **Feature queries:** `(prefers-reduced-motion: reduce)` - progressive enhancement is deliberate here.

**Fluid type:** sizes interpolate with `clamp()` / viewport units rather than stepping at breakpoints - copy the real expressions:
